### **Signed Commits and Tags in Git**

Signed commits and tags in Git add **cryptographic verification** to ensure authenticity. They help prevent forgery and allow users to verify the **integrity** of commits and tags. This is especially useful in **open-source projects** and **collaborative repositories** where security is a concern.

---

## **1. Why Use Signed Commits and Tags?**

🔹 **Verifies authenticity**: Ensures that a commit or tag was created by the intended author.  
🔹 **Prevents tampering**: Signed commits cannot be altered without invalidating the signature.  
🔹 **Required for security-sensitive projects**: Many organizations enforce signed commits and tags.

---

## **2. Configuring GPG for Signed Commits**

Git uses **GPG (GNU Privacy Guard)** to sign commits and tags.

### **Step 1: Check if GPG is Installed**

`gpg --version`

🔹 If not installed, download it from GnuPG.

### **Step 2: Generate a GPG Key (if you don’t have one)**

`gpg --full-generate-key`

🔹 Choose **RSA (4096 bits)** for better security.  
🔹 Set an **expiration date** or select **no expiration**.  
🔹 Provide your **name** and **email** (should match your Git config).  
🔹 Set a **secure passphrase**.

### **Step 3: Get Your GPG Key ID**

`gpg --list-secret-keys --keyid-format LONG`

🔹 Find the **long key ID**, which looks like `123456789ABCDEF`.

### **Step 4: Configure Git to Use Your GPG Key**

`git config --global user.signingkey 123456789ABCDEF git config --global commit.gpgsign true  # Sign all commits by default`

🔹 Replace `123456789ABCDEF` with your actual GPG key ID.

---

## **3. Creating a Signed Commit**

To sign a commit manually:

`git commit -S -m "This is a signed commit"`

🔹 The `-S` flag tells Git to sign the commit.  
🔹 If prompted, enter your GPG passphrase.

To verify a signed commit:

`git log --show-signature`

🔹 Shows whether the commit was signed and by whom.

---

## **4. Creating Signed Tags**

A **signed tag** is like a normal Git tag but includes a **cryptographic signature**.

To create a **signed tag**:

`git tag -s v1.0.0 -m "Signed version 1.0.0"`

🔹 The `-s` flag creates a signed tag.

To verify a signed tag:

`git tag -v v1.0.0`

🔹 If valid, Git will confirm the signature and display the associated GPG key.

---

## **5. Enforcing Signed Commits and Tags**

Many projects require all commits and tags to be signed. You can enforce this using Git hooks or repository settings.

### **Require Signed Commits Locally**

`git config --global commit.gpgsign true`

🔹 Ensures **all commits are signed** by default.

### **Require Signed Commits in a Repository**

In GitHub/GitLab, you can enforce signed commits using **branch protection rules**.

For GitHub:

1. Go to **Repository Settings → Branches**.
2. Enable **Require signed commits** under "Branch Protection Rules".

---

## **6. Summary**

✅ **Signed commits and tags** verify authenticity and prevent tampering.  
✅ **GPG keys** are used to sign commits and tags.  
✅ **Signed commits (-S)** ensure commit integrity.  
✅ **Signed tags (-s)** are cryptographically verifiable.  
✅ **GitHub/GitLab can enforce signed commits** for better security.
