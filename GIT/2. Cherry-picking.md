### **Git Cherry-Picking**

**Cherry-picking** in Git allows you to **selectively apply specific commits** from one branch to another, without merging the entire branch. This is useful when you want to apply a particular fix, feature, or change without bringing unrelated commits along.

---

### **1. Basic Cherry-Picking**

To apply a specific commit from another branch:

📌 **Command:**

`git checkout target-branch git cherry-pick <commit-hash>`

🔹 This takes the commit with the specified hash and applies it to the current branch.

✅ **Use Case:** If a bug fix exists on a feature branch but needs to be added to `main` separately.

---

### **2. Cherry-Picking Multiple Commits**

You can cherry-pick **multiple commits** at once:

📌 **Command:**

`git cherry-pick <commit-hash1> <commit-hash2> <commit-hash3>`

🔹 This applies the selected commits in order to the current branch.

Alternatively, to pick a **range of commits**:

`git cherry-pick <start-commit>^..<end-commit>`

🔹 This applies all commits between `start-commit` and `end-commit`.

---

### **3. Cherry-Picking with Conflict Resolution**

If conflicts arise:

`git status  # Identify conflicting files # Manually resolve conflicts git add <resolved-file> git cherry-pick --continue  # Continue after resolving`

To abort cherry-picking:

`git cherry-pick --abort`

---

### **4. Cherry-Picking with Commit Messages**

If you want to modify the commit message during cherry-picking:

`git cherry-pick -e <commit-hash>`

🔹 This opens the editor, allowing you to **edit the commit message** before applying.

---

### **5. Cherry-Picking Without Committing (`--no-commit`)**

To stage the changes from a commit but **not commit them immediately**:

`git cherry-pick -n <commit-hash>`

🔹 This applies the changes, but you must commit them manually:

`git commit -m "Applying selected commit"`

✅ **Use Case:** When merging multiple cherry-picked commits into a single commit.

---

### **6. Cherry-Pick vs. Merge vs. Rebase**

|Feature|Cherry-Picking|Merging|Rebasing|
|---|---|---|---|
|Purpose|Apply specific commits|Combine branches|Move commits onto another branch|
|Commit History|Preserves only selected commits|Keeps full branch history|Rewrites history|
|Conflict Risk|Medium|Lower|Higher|
|Use Case|Applying bug fixes or features selectively|Integrating full feature branches|Keeping history clean|

---

### **7. When to Use Cherry-Picking**

✅ Apply bug fixes to multiple branches (e.g., from `develop` to `main`).  
✅ Extract a specific feature from a larger branch.  
✅ Avoid merging unnecessary changes.

⚠️ **Avoid excessive cherry-picking**, as it can lead to **fragmented commit history** and make tracking changes harder.

---

### **🔍 Summary:**

✅ **Cherry-pick** for applying specific commits without merging.  
✅ **Use `-n`** to stage changes without committing.  
✅ **Resolve conflicts carefully** when cherry-picking across branches.
