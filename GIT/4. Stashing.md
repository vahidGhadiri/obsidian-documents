### **Git Stashing**

**Git Stashing** allows you to temporarily save (stash) your uncommitted changes **without committing them**, so you can switch branches or work on something else without losing your progress. Later, you can retrieve and reapply the stashed changes when needed.

---

### **1. Basic Stashing**

To stash all uncommitted changes:

`git stash`

🔹 This saves your modified and staged files in a **hidden stash stack** and resets your working directory to match the last commit.

✅ **Use Case:** You’re working on a feature but need to quickly switch branches without committing incomplete work.

---

### **2. Viewing Stashes**

To see all stashed entries:

`git stash list`

🔹 Each stash is labeled as `stash@{n}`, where `n` is an index (e.g., `stash@{0}`).

---

### **3. Applying Stashes**

To apply the latest stash without removing it from the stash stack:

`git stash apply`

🔹 If conflicts occur, resolve them manually and commit the changes.

To apply a specific stash:

`git stash apply stash@{2}`

To apply a stash and remove it from the stack:

`git stash pop`

🔹 This is like `apply`, but it also **deletes** the stash after applying.

✅ **Use Case:** You want to restore saved changes and continue working.

---

### **4. Removing Stashes**

To delete the latest stash:

`git stash drop`

To delete a specific stash:

`git stash drop stash@{2}`

To **clear all** stashed changes:

`git stash clear`

🚨 **Warning:** This permanently deletes all stashes!

✅ **Use Case:** You no longer need the stashed changes and want to free up space.

---

### **5. Stashing with Message**

To label your stash for easy reference:

`git stash save "WIP: Fixing login bug"`

To list stashes with messages:

`git stash list`

🔹 Messages help you identify what each stash contains.

✅ **Use Case:** You’re working on multiple tasks and want to differentiate stashes.

---

### **6. Stashing Untracked Files**

By default, `git stash` only saves modified **tracked files**. To stash **untracked files** as well:

`git stash -u`

To stash **ignored and untracked files**:

`git stash -a`

✅ **Use Case:** You’ve added new files but aren’t ready to commit them.

---

### **7. Stashing Specific Files**

To stash only specific files:

`git stash push -m "Partial stash" -- <file-path>`

✅ **Use Case:** You want to save changes from only one file while keeping others untouched.

---

### **8. Creating a Branch from a Stash**

To move stashed changes into a new branch:

`git stash branch new-feature-branch`

🔹 This creates a branch from the commit where you stashed changes and applies the stash there.

✅ **Use Case:** You realize your stashed changes should become a separate feature branch.

---

### **9. Stash vs. Commit vs. Reset**

|Feature|Stash|Commit|Reset|
|---|---|---|---|
|Purpose|Temporarily save changes|Save changes permanently|Discard changes|
|Affects history?|No|Yes|Yes|
|Use Case|Switching tasks quickly|Finalizing work|Undoing mistakes|

---

### **10. When to Use Stashing**

✅ Switching branches without committing.  
✅ Experimenting without affecting history.  
✅ Saving work-in-progress (WIP) changes.

⚠️ **Don’t overuse stashing**—it can lead to forgotten or lost changes!

---

### **🔍 Summary:**

✅ `git stash` saves uncommitted changes temporarily.  
✅ Use `git stash list` to view stashes.  
✅ `git stash apply` restores changes without deleting them.  
✅ `git stash pop` restores and removes the stash.  
✅ `git stash branch` moves stashed changes to a new branch.
