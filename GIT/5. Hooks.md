### **Git Hooks**

**Git Hooks** are scripts that run automatically at specific points in the Git workflow. They allow you to automate tasks like **linting, formatting, running tests, or enforcing commit message conventions**. Hooks can be triggered before or after actions like commits, pushes, merges, and checkouts.

---

## **1. Types of Git Hooks**

### **1.1 Client-Side Hooks**

These run on your local machine and help enforce code quality and workflow automation.

|Hook Name|When It Runs|Common Use Cases|
|---|---|---|
|`pre-commit`|Before a commit is created|Run linters, format code, check file sizes|
|`prepare-commit-msg`|Before commit message editor opens|Pre-fill commit messages with templates|
|`commit-msg`|After commit message is entered|Enforce commit message conventions|
|`pre-push`|Before pushing to remote|Run tests, check for API key leaks|
|`pre-rebase`|Before a rebase starts|Prevent rebasing certain branches|
|`pre-merge-commit`|Before merging a commit|Ensure merge conflicts are resolved|

### **1.2 Server-Side Hooks**

These run on the **Git server** and help enforce rules before code enters a shared repository.

|Hook Name|When It Runs|Common Use Cases|
|---|---|---|
|`pre-receive`|Before processing push on the server|Reject bad commits, enforce branch policies|
|`update`|Before updating refs on the server|Restrict force pushes or branch deletions|
|`post-receive`|After a push is received|Deploy code, notify CI/CD pipelines|

## **2. Setting Up a Git Hook**

### **2.1 Creating a Hook**

Git hooks are stored inside the `.git/hooks/` directory of a repository. To create a new hook:

1️⃣ **Navigate to hooks folder:**

`cd .git/hooks`

2️⃣ **Create a new hook (e.g., `pre-commit`):**


`touch pre-commit chmod +x pre-commit  # Make it executable`

3️⃣ **Edit the hook script:**


`nano pre-commit`

4️⃣ **Add your script (Example: Prevent committing debug statements)**


`#!/bin/sh if grep -R "console.log" .; then   echo "❌ Remove console.log statements before committing!"   exit 1 fi`

5️⃣ **Save and exit** (`CTRL+X`, then `Y`, then `ENTER`).

Now, every time you try to commit, Git will check for `console.log` statements and reject the commit if found.

## **3. Useful Git Hooks Examples**

### **3.1 Enforce Commit Message Format (`commit-msg`)**

Ensure all commits follow the **Conventional Commits** format:

`#!/bin/sh commit_msg=$(cat "$1") if ! echo "$commit_msg" | grep -Eq "^(feat|fix|chore|docs|test|refactor|style|perf|ci): .{10,}"; then   echo "❌ Commit message must follow: 'feat|fix|chore|docs|test|refactor|style|perf|ci: [description]'"   exit 1 fi`

✅ **Use Case:** Ensure meaningful commit messages.

---

### **3.2 Run Tests Before Pushing (`pre-push`)**

Prevent pushing code if tests fail:

`#!/bin/sh echo "🚀 Running tests before push..." npm test  # Run tests if [ $? -ne 0 ]; then   echo "❌ Tests failed! Fix them before pushing."   exit 1 fi`

✅ **Use Case:** Avoid breaking the CI/CD pipeline.

---

### **3.3 Check for Large Files (`pre-commit`)**

Prevent committing files larger than 1MB:

`#!/bin/sh max_size=1048576  # 1MB in bytes for file in $(git diff --cached --name-only); do   if [ -f "$file" ] && [ $(stat -c%s "$file") -gt $max_size ]; then     echo "❌ File $file exceeds 1MB limit. Reduce size before committing."     exit 1   fi done`

✅ **Use Case:** Prevent committing unnecessary large files.

## **4. Managing Hooks with Husky (for JavaScript Projects)**

For easier hook management in **JavaScript/TypeScript projects**, use **Husky**:

`npm install husky --save-dev`

Enable hooks in **package.json**:

`npx husky install`

Create a `pre-commit` hook:

`npx husky add .husky/pre-commit "npm run lint && npm test"`

✅ **Benefit:** No need to manually place scripts in `.git/hooks/`.

---

## **5. Disabling Hooks (Temporarily Bypass)**

If you need to commit without triggering hooks:

`git commit --no-verify`

✅ **Use Case:** Bypass hooks in emergencies.

---

## **6. Summary**

✅ **Git Hooks** automate tasks before or after Git actions.  
✅ **Client-side hooks** help with linting, formatting, testing, and commit message enforcement.  
✅ **Server-side hooks** enforce security and deployment policies.  
✅ **Use Husky** for better hook management in JavaScript projects.  
✅ **Temporarily bypass hooks** using `--no-verify`.
