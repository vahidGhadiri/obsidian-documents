### **Git Reflogs: Recovering Lost Commits and Undoing Mistakes**

Git **Reflog (Reference Logs)** is a powerful feature that tracks the movement of HEAD and branches over time. It allows you to **recover lost commits, undo actions, and navigate your Git history safely**. Unlike `git log`, which only shows commits reachable from branches, **reflogs track everything—including deleted branches, resets, and rebases**.

---

## **1. Understanding Reflogs**

- **Every time HEAD or a branch moves**, Git logs the change in the reflog.
- **Reflogs are local**—they do not exist in remote repositories.
- **Entries expire after 90 days** (default) unless manually extended.

### **Example: Viewing the Reflog**

`git reflog`

🔹 Shows all movements of HEAD and branches.

#### **Example Output**

`a1b2c3d (HEAD -> main) HEAD@{0}: commit: Fix bug in checkout flow 4e5f6g7 HEAD@{1}: merge feature-x: Merge made by the 'recursive' strategy 8h9i0j1 HEAD@{2}: reset: moving to HEAD~2 2k3l4m5 HEAD@{3}: checkout: moving from feature-x to main`

- `{0}`: The most recent action
- `{1}, {2}, {3}`: Older actions

---

## **2. Recovering Lost Commits**

Sometimes, you may accidentally delete a branch or reset your HEAD to an older commit. **Reflog helps recover those lost commits**.

### **Scenario 1: Accidentally Deleting a Branch**

`git branch -D feature-x`

🔹 Deletes `feature-x`, but the commits are not truly lost.

**Solution: Restore the Deleted Branch**

`git checkout -b feature-x HEAD@{1}`

🔹 Creates a new branch from the last recorded position of `feature-x`.

---

### **Scenario 2: Resetting HEAD by Mistake**

`git reset --hard HEAD~3`

🔹 Moves HEAD **3 commits back**, discarding changes.

**Solution: Recover the Last Commit**

`git reset --hard HEAD@{1}`

🔹 Moves HEAD back to where it was before the reset.

---

## **3. Undoing a Bad Merge**

If you merge branches but later realize it was a mistake, you can **undo the merge using reflog**.

`git merge feature-x`

🔹 Merges `feature-x` into `main`.

**Solution: Undo the Merge**

`git reset --hard HEAD@{1}`

🔹 Restores the state before the merge.

---

## **4. Using Reflog to Restore an Older Version**

If you realize that a previous commit had a better state, you can check its reflog entry and move HEAD there.

`git checkout HEAD@{5}`

🔹 Moves to the state from 5 reflog entries ago.

If you want to **create a new branch** from that state:

`git checkout -b restore-point HEAD@{5}`

---

## **5. Cleaning Up Reflog Entries**

Reflogs automatically expire, but you can **manually clean them** using:

`git reflog expire --expire=now --all git gc --prune=now`

🔹 Removes old reflog entries and optimizes storage.

---

## **6. Summary**

✅ `git reflog` tracks every movement of HEAD and branches.  
✅ You can **recover deleted branches, reset mistakes, and undo merges**.  
✅ **Use `HEAD@{n}`** to reference previous states.  
✅ **Reflogs are local** and do not exist on remotes.
