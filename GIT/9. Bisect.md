### **Git Bisect: Finding the Buggy Commit Efficiently**

Git **bisect** is a powerful tool that helps you quickly **identify the exact commit that introduced a bug**. It automates a **binary search** through the commit history, reducing the number of steps needed to locate the problematic commit.

---

## **1. How Git Bisect Works**

Instead of checking every commit manually, Git bisect **divides the commit history into halves**, allowing you to find the bad commit in **log₂(N) steps**, where **N** is the number of commits.

For example, if you have 1000 commits, **Git bisect finds the bad commit in ~10 steps** instead of checking all 1000 commits!

---

## **2. Starting Git Bisect**

### **Step 1: Start the Bisect Process**

`git bisect start`

🔹 Begins the bisect session.

### **Step 2: Mark a Known Good Commit**

`git bisect good <commit-hash>`

🔹 This should be a commit **before the bug appeared**.

### **Step 3: Mark a Known Bad Commit**

`git bisect bad <commit-hash>`

🔹 This should be a commit **where the bug is present**.

### **Step 4: Git Checks Out the Middle Commit**

Git will automatically **checkout a commit halfway between the good and bad commits**.

Test this commit:

- If **the bug is present**, mark it as **bad**:
    
    `git bisect bad`
    
- If **the bug is not present**, mark it as **good**:

    `git bisect good`
    

Git will continue checking out commits in the middle until it finds the exact commit that introduced the bug.

---

## **3. Automating Git Bisect (Optional)**

Instead of manually testing each commit, you can **automate Git bisect** with a script.

Example:

`git bisect run ./test-script.sh`

🔹 Runs `test-script.sh` on each commit automatically until the bad commit is found.  
🔹 The script should **exit with 0** if the commit is good and **non-zero** if the commit is bad.

---

## **4. Finishing the Bisect Process**

Once Git finds the problematic commit, **reset the repository**:

`git bisect reset`

🔹 Returns to the branch’s original state before bisecting.

---

## **5. Example Scenario**

### **Step 1: Start Bisect**

`git bisect start`

### **Step 2: Define the Good and Bad Commits**

`git bisect good abc123  # A commit where everything worked git bisect bad xyz789    # A commit where the bug exists`

### **Step 3: Test and Mark Commits**

Git checks out a commit in the middle.

- If the bug is **present**, mark it as bad:
    
    `git bisect bad`
    
- If the bug is **not present**, mark it as good:
    
    `git bisect good`
    

### **Step 4: Git Finds the Bad Commit**

After a few steps, Git prints:

`xyz456 is the first bad commit`

🔹 This is the commit where the bug was introduced.

### **Step 5: Reset Bisect**

`git bisect reset`

🔹 Returns to the previous branch.

---

## **6. Summary**

✅ **Git bisect speeds up debugging** by using a **binary search** approach.  
✅ **You define a good and a bad commit**, and Git **checks out the middle commit** to help narrow down the issue.  
✅ **Mark commits as good or bad** until Git finds the first bad commit.  
✅ **You can automate the process** using a test script.
